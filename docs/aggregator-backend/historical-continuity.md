# B4 historical continuity

B4 is an internal read-only composition of the existing administration captures.
The existing manager-history page remains on its current reader. Official weekly
results, provider ownership, curated effective attribution and curated honors are
separate facts. No collection, writer, migration, backfill, scoring or cron change
is needed: the retained v1 documents and content-linked team identities already
represent this bounded resource.

## Bounded acceptance matrix

| Case | Required result |
| --- | --- |
| Normal annual history | Follow exact `previous_league_id`, exact previous year, completed status and registered permanent league; preserve season/team UUIDs and provider account IDs. |
| Scope | League One starts 2024; League Two and Dynasty start 2025; at most 20 seasons, Weeks 1–14 only, narrowed by an earlier playoff start. Current season counts only a proved completed-week boundary. |
| Missing or partial | Keep established participants and source ages; withhold combined records and report the existing warning. Missing evidence never means zero. |
| Conflict | Reject repeated/circular/wrong-season links, mismatched mappings, ambiguous ownership or source changes during capture. Names never establish continuity. |
| Official corrections | Preserve raw/custom/effective exact points and existing win/loss/tie calculation; a new accepted capture may change results without mutating the prior frozen comparison. |
| Curation | Retain source primary/co-owner relationships; label the approved League Two override separately. Honors identify original league/year and owner-supplied provenance, never provider playoff results. |
| Unsupported | Median, best-ball or unsupported season settings retain the established warning and unavailable aggregate. |
| Historical time | Reuse completed-season verification policy; pre-final scores cannot be finalized by newer configuration alone, and current metadata cannot establish historical ownership or player state. |
| Restart | Serialize the bounded frozen input and reproduce identical internal and compatibility results without reads, writes, changed source times or invented mapping evidence. This is not durable persisted replay. |
| Compatibility and rollback | Compare the current history aggregation against the same frozen source input; old readers and immutable observations remain available unchanged. |

## Capture and qualification boundary

Annual discovery and reviewed imports continue through the existing administration
operator, Sleeper adapter, normalizer and writer. The internal reader selects
registered season mappings and accepted documents through the same store and
page-source temporal guards. It has no provider or write capability. A missing
retained document stays unavailable; it does not trigger another acquisition.

Each comparison freezes source identities, generations, original provenance and
the evaluation time. A final mapping/source check rejects concurrent changes.
Historical mapping gaps remain visible rather than being filled with today's
mapping. Corrections require a new capture; a frozen input remains reproducible.

Raw, custom and effective provider points remain exact. The compatibility record
and weekly `compatibilityResult` deliberately reuse the existing completed-result
calculator, which compares scores at hundredths precision. That presentation
policy is labeled as League One derivation; B4 does not change scoring or present
it as a newly supplied provider winner field. Source-team identity completeness
is reported separately from usable provider-scoped historical records.

The manifest retains rejected-source observation IDs, verification ages and guard
reasons without admitting their values into the result. It also freezes the
current calendar/context evidence and evaluation time used to determine eligible
weeks. Source and result digests detect changes to evidence or transformation.
The existing v1 store exposes timestamps at JavaScript millisecond precision;
this resource does not claim to preserve additional SQL timestamp digits. Head
check time is labeled separately; original observation check time stays unknown
unless the retained roster bridge proves it.

Ordinary tests, independent review, actual Preview, exact-SHA disposable SQL and
production coverage are separate evidence gates. No paid SQL run, production
migration, production processing, reader cutover or release is authorized by this
implementation. Current status belongs in the Step 2 ledger and, after source
freeze, the PR body and ignored evidence artifacts.
