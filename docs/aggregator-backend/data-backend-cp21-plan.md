## Fresh installation path and platform normalization

This profile qualifies the existing disposable **role-first** path: the supervisor proves the child empty and all three restricted roles absent, creates three fresh NOINHERIT LOGIN identities, then uses the existing harness to install all migrations and apply all maintained provisioner grants. The initial witness must precede role creation and schema reset; a post-reset empty schema cannot substitute for it. This does not execute or qualify the standalone migration-first CLI or each provisioner CREATE ROLE branch. CP1/CP2 row 21 do not prescribe an installation order.

Only verified installer and bootstrap identities are normalized. A superuser installation has exactly three installer-to-application inbound membership rows. A nonsuperuser CREATEROLE installation has the three additional automatic membership rows granted by verified bootstrap role OID 10, with ADMIN true, INHERIT false and SET false; the installer separately grants itself ADMIN false, INHERIT true and SET true. Application roles gain no outbound membership. Other grantors, edges or flags are rejected. The frozen catalog compares exact function signatures, owners and grantors; trusted-extension ownership must be explicitly evidenced and frozen rather than tolerated as arbitrary owner drift.

The candidate remains incomplete until focused checks, exact-body offline diagnostics with their limitations, independent final review, the complete normal source workflow, draft PR, normal CI and inspection of the exact Vercel preview are recorded.
