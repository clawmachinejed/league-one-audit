# Automatic league capability reports

My Leagues assesses each discovered league's public Sleeper settings automatically, using the existing bounded user-league response. Each card has a Website compatibility disclosure. Missing, malformed or contradictory settings make the affected report unverified without hiding a valid league name or Sleeper link. This check does not enroll a league, activate website pages, create a collector, call Tank01, or assert current lineup/data completeness.

The shared `assessSleeperLeagueCapabilities` function checks roster slot types, actual scoring events, projection events, projected standings, schedules/history and substitutions. The report distinguishes supported, limited, unsupported and unverified features. Its aggregate status is the highest concern, not permission to import a league. Existing account-session, association, private-cache and stale-response checks still apply to the response.

Scoring checks reuse the existing scorer's Sleeper event normalization and actual-stat allowlist. The report performs no scoring arithmetic and has no league-specific names, email addresses or identities in its policy. Actual event coverage and projection support remain distinct: qualifying a native actual stat does not supply missing projection statistics. The existing long-touchdown/defense bonus omissions and points-allowed approximation remain explicitly limited; new unsupported events do not silently inherit those exceptions. See [the native-event evidence and additive database qualification](scoring-event-coverage.md).

Reports include a version, assessment time, raw scoring-rule hash and material configuration revision. Reordering dictionary keys or advancing operational counters does not change the configuration revision. Changed scoring weights, roster order, team count, season or material competition settings do. The next normal discovery read reevaluates the settings and current code capabilities; the shared Sleeper cache remains 60 seconds. Assessment time does not claim a fresh upstream observation. No separate stored rule source or per-account rule copy is created. Enrolled leagues retain their existing immutable Neon profiles, configuration history and publication lineage.

The report is conservative. Unknown active scoring events are unsupported; missing input and unfamiliar competition fields are unverified. Known Sleeper AutoSubs settings (0–3 substitutions and boolean timing/lock flags) are supported by consuming official starter changes through the shared lineup revision and snapshot pipeline. Incoming players use their own kickoff baseline; the site does not predict or execute a pending substitution. Other substitution settings remain unverified.

Distance-based kicking and rare-event bonuses use the explicitly limited [supplemental projection model](supplemental-projections.md). The report still exposes the Week 1/head-to-head/no-division restriction for projected standings and the current 14/15-week history/schedule limits. Known supported slot labels do not prove complete lineups, future player crosswalks, capacity or playoff seeding. League One/Two presentation customizations and the single canonical calculator remain unchanged.

Collection failure isolation remains required before enrolling unrelated leagues. Capacity qualification and full route/enrollment automation are separate work. Migration 022 and the application require their ordinary reviewed production release; a report saying a scoring event is supported is not evidence that a pending database migration has been installed.
